# Paged public owner portfolio

Convex remains the backend. Furnished Finder's [landlord profile guide](https://support.furnishedfinder.com/hc/en-us/articles/35051103266715-Setting-Up-Your-Landlord-Profile) (updated September 4, 2026; checked October 26) describes previewing the public profile separately from editing it. This change preserves the existing profile UI and reviews, biography, pets, identity labels and listing-card links.

The public owner page previously called the legacy management-compatible array query. That query collected the whole portfolio and returned private management rows when the caller was the owner or staff. The profile could therefore show a different portfolio from what visitors could see and label a partial/management-derived count as Total Listings.

`publicOwnerListings.list` now pages at most ten active owner candidates using `(landlordId, status, createdAt)`, in newest creation-date order. It rechecks current publication, content, approval revision, owner identity/paid access, shared-unit and moderation requirements for every card. Missing, non-landlord or offboarded owners end the list. The query intentionally gives anonymous visitors, owners and staff the same result. Its explicit return validator allows only listing-card fields and one resolved cover image; it does not expose exact address/ZIP, description, private photo metadata, owner IDs, publication issues, approval/review details or management state.

An empty candidate page preserves continuation. The profile reports public listings loaded, distinguishes records not yet checked from exhaustive no-public-listings results, and offers Check more or Load more. There is no automatic whole-portfolio loading or false total. Existing card routes and Reviews tab remain. Neither private owner entry point nor the public profile now uses `getByLandlord`. That legacy array API remains for small existing callers, reads at most 101 candidates and explicitly refuses portfolios exceeding 100 with a pagination instruction; it does not silently truncate a list or scan arbitrarily many held rows before its cap. Its public branch uses the same card allowlist plus public amenities, empty address and active status; management/review/photo metadata is reserved for authenticated management reads. Existing callers needing larger portfolios must migrate to the private/public paginated API.
