# Recorded map eligibility

Reference checked October 25, 2026: [Furnished Finder listing performance](https://support.furnishedfinder.com/hc/en-us/articles/34672767306907-How-Can-I-Track-Views-or-My-Listing-Performance) includes the number of days a property qualifies to appear on the search map, with daily panel updates. Our own counts use actual native qualification checks; competitor start dates and totals are never copied.

The private Listing performance page now shows recorded eligible UTC days for a selected rental space, current eligibility, days with checks, a daily table and an eligibility CSV. Portfolio totals count rental-space days: two eligible spaces on one date count as two. Since-collection totals remain after old daily rows leave the 90-day report. Earlier history is unavailable, even if a listing has a much older first-published date or legacy view counter.

## Measurement contract

A positive check requires the actual current `publiclyVisible` predicate, including owner intent, approved current revision, content/property-group requirements, moderation/identity gates, current paid landlord entitlement and plan capacity, plus finite in-range approximate map coordinates. This is eligibility for an unfiltered map; specific dates, map bounds or traveler filters can still exclude the listing. Qualification does not mean an actual pin/impression was displayed.

At most one positive is counted per rental space, owner, environment and UTC day. Repeated/concurrent checks, scans, publishing and later hiding cannot add the same day again or erase an earlier positive. Current eligibility is checked independently of that historical positive. A negative row means the rental was not observed eligible at its check times; it does not establish full-day absence. Missing rows stay unavailable and export blank values. Brief eligibility between checks may be unrecorded; this report does not reconstruct continuous eligibility intervals or provide a complete zero-filled history.

Daily collection shares the durable paged market-inventory worker and its existing cursor/recovery fencing. Every currently stored rental is checked, including drafts and hidden spaces, with checks attributed to their actual execution date if a run crosses midnight. Supported publication, map/location, unit synchronization and staff-hold changes also record native checks. View-only map sorting updates do not manufacture an eligibility observation. Owners/staff can explicitly check a selected space; the client supplies no qualification flag or date.

Private per-space and per-owner day tables deduplicate atomically. Independent since-collection counters update in the same transaction and initialize once from existing retained native checks when upgrading this collector. Initialization makes no claim about unavailable older data. Indexed bounded cleanup removes daily rows older than the rolling history allowance while preserving counters and their collection-start timestamp. Test and production rows/counters are separate; ownership changes do not expose another owner's property history. Portfolio history retains observations attributed to that owner at the time. Queries read at most 91 indexed day rows plus the native counter, with explicit 7/30/90-day windows. CSV contains only dates, environment, scope, coverage, space counts and UTC check times; no address, contact or precise coordinate is included.
