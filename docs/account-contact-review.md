# Precautionary account contact reviews

Staff can pause contact for the account reported in a property or received-message case, with a private reason in the existing support audit. Creating a report does not restrict an account. The account target is bound to the original native listing owner/message sender; callers cannot nominate a user. New reports retain that binding after the source changes or disappears. Legacy reports use a surviving native source and never trust evidence JSON to choose an account. Ordinary support cases, staff accounts and deleted sign-in accounts cannot receive a new contact-review action.

Each case has its own indexed hold and revision. Staff actions require the expected current revision; stale writes fail. Releasing one case releases only its restriction. Contact stays paused while any other case is active or a participant block prevents communication. Private review targets, notes, evidence and hold details are staff-only; the reported account and unrelated users cannot read the report. Requesters see their own case without staff-only fields. This is human staff review, with no automatic classification or housing eligibility decision.

The shared native communication guard pauses new marketplace messages in both directions, lead replies, selected-rental phone disclosure, listing-phone reveals and queued contact notifications before their existing provider-attempt checks. Existing contact-gated inquiry, booking-change, document-share/signing and rental-tool setup actions use the same guard. Current owner phone availability also fails closed before prompting anonymous viewers to sign in. Phone consent, proof, preferences and user blocks are not rewritten. Numbers already copied or provider work already in flight cannot be recalled. Support submissions/replies and existing participant history remain available. Existing stays, financial records, requests and publication state are not deleted or automatically cancelled; listing moderation remains a separate action. External signing links already issued are a separate revocation gate.

Delivered leads remain visible with an account-review notice and disabled matching/composition controls. They do not expose phone details. Existing conversations open read-only with a review explanation. Releasing all restrictions restores the underlying contact eligibility checks; it does not override a user's block, restore deleted leads, grant missing phone consent or publish private rentals. Release itself sends no new message or notification.

Validation: 394 tests across 36 files, TypeScript and Next production build pass. Seven review cases cover staff authority and private projections, stale revisions, multiple-case release, native phone/message/lead denial, support/history access, original/legacy/deleted-source bindings, independent blocks and removed leads, anonymous phone availability and meaningful positive-to-suppressed notification controls. Native local public-unit tests use explicit synthetic paid/identity/staff prerequisites and restore fixture publication/capacity. Hosted checks use actual Clerk sessions for the owner, disposable traveler and a newly provisioned disposable development staff account. The staff role is deliberately assigned in the isolated native QA database; JWT role claims, paid or identity entitlements are not forged. The lead/rental history is explicitly privileged and private. This proves native review authority and contact guards; real production staff operations, real public cloud phone/SMS/provider acceptance and full staff-browser acceptance remain open. Fixtures release their review before disposable accounts are removed; private native audit/history remain.
