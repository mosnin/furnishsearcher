# Public property payloads and rental highlights

Convex remains the backend. Furnished Finder's [property/unit viewing guide](https://support.furnishedfinder.com/hc/en-us/articles/51593395190299-How-Do-I-View-My-Property-or-Unit-Listing) distinguishes management navigation from the traveler-facing listing (checked October 26, 2026). This change preserves existing UI styles and property functionality while separating editing metadata from public responses.

`publicListingDetail` explicitly projects the full public property content: description, rent/occupancy/stay terms, room/bath/fee/rule/facility details, normalized amenities, full resolved photo order and matching captions, public unit/group references and approximate map point. Street address and ZIP remain blank for public callers. Native photo-asset/editor-draft objects, publication/review revisions, request/hold state, payment references, normalized indexing keys, location-generation/confirmation records, first-publication and calendar-sync metadata are omitted. Public image URLs intentionally remain usable; this is a field/privacy boundary, not a claim that a public image URL hides its asset identity.

`listings.getById` starts from that public projection and overlays the full hydrated native listing only for the actual active owner/staff manager. Current publication checks and public/private preview flags remain unchanged. Owners retain exact location, photo drafts/storage attachment metadata and revision data needed for editing. The editor refuses missing/non-managed rows before loading its form; a missing listing no longer remains on a skeleton forever. Legacy public array search uses the same public detail projection. The existing paginated search and public owner-card allowlists remain separate.

The six-card highlight query now has a return allowlist, one cover per card, and a public owner ID needed for the existing Message handoff. Current verified paid sponsorship, visibility and billing mode still gate every returned placement. An index binds featured mode/flag/active status/expiry. At most sixty promoted and sixty recent active candidates are read; held/ineligible candidates do not trigger an unbounded database filter. Up to six verified paid cards precede recent fallback cards. Once six fallback cards exist, unverified candidates avoid gallery hydration. This is a bounded showcase, not an exhaustive inventory count; full marketplace search stays paginated and can find valid records beyond this window.

Homepage and traveler dashboard now call this section Rental Highlights and describe public rentals rather than claiming personal recommendations, human curation, immediate availability or daily additions. Their empty state points to full search. The homepage had dropped the trusted sponsorship flag while mapping cards; it now forwards it. Traveler dashboard cards also label verified Sponsored placements. Public owner IDs are preserved so Message links do not become undefined after payload minimization.
