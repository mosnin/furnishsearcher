# Inquiry acknowledgements and private listing previews

Convex remains the backend. Furnished Finder's current [live-listing guide](https://support.furnishedfinder.com/hc/en-us/articles/35067571452699-Is-My-Listing-Live) (updated October 2, 2026; checked October 26) distinguishes a live traveler-visible listing from an inactive/incomplete owner listing. The app already gates new inquiries and messages on publication; this work makes owner previews explicit and makes first contact recoverable after an interrupted acknowledgement.

Inquiry creation accepts an optional UUIDv4 reference for compatibility. A `(tenantId, clientRequestId)` index checks existing saved work after authenticating the active account and before creating new work. A replay must match the original listing, original dates, party size, pets and trimmed message; altered payloads fail. An exact replay returns the original ID even if the owner has since confirmed, changed dates, hidden the listing or cancelled the request. It does not reopen, revalidate or overwrite that stay, create a new message, repeat notification work or add counters. New references still run all current publication, contact, stay/availability, occupancy, pet and duplicate-pending-date checks. Empty/malformed supplied references fail. Existing callers without a reference retain their behavior. Booking's participant return validator includes the new optional native field.

The inquiry form retains a stable reference for one exact draft, creates a new one after payload changes and prevents overlapping handlers/closing during a send. Its form state is keyed by listing, account and search-link dates so a different property/account or changed date handoff cannot reuse the old form state. Contact uses the existing native message reference with the same exact-draft retry behavior, blocks concurrent sends, removes its delayed reset race and scopes modal state by property/account. Successful contact says the message is saved and links to the inbox; it does not promise a reply or email delivery. Missing app profiles have completion links rather than a silent contact action.

`listings.getById` now derives `isPublic` from current native publication requirements and `canManage` from the actual active owner/staff identity. Private rows remain inaccessible to visitors. The detail page labels an authorized private preview, links to editing and publication requirements, and hides traveler inquiry/contact/phone/save/share/report/review-submission controls. Public owner/staff views also use management guidance rather than self-contact controls, while public sharing remains available. This is a display/access clarification, not a new publication grant; native mutations continue enforcing their own authority.

Validation: 486 tests / 44 files, TypeScript and Next production build pass. Six new inquiry tests cover concurrent deduplication and single message/event/performance effects; payload binding; replay after actual confirmation, agreed extension and unpublishing without calendar/event changes; actor isolation/anonymous/deleted-account refusal; withdrawn replay versus deliberate fresh attempt; and malformed references. A seventh test proves owner/staff private-preview versus traveler public flags/denials.

`scripts/local-inquiry-retry-smoke.mjs` verifies real loopback Convex transactions under explicitly synthetic local publication prerequisites and privileged local identities. It guards the anonymous endpoint and exact dummy billing/disabled-email configuration before mutation, creates and publishes only its named synthetic rental, verifies simultaneous inquiry/contact deduplication, confirms and extends the stay, hides the rental, checks replay without calendar/event changes, cancels it and confirms replay does not reopen it. Cleanup deletes its exact rental and retains the cancelled QA inquiry/history. This is not an actual Clerk browser inquiry, live provider approval or hosted public booking. Receipt: `docs/evidence/local-inquiry-retry-native.json`.

The read-only public-profile smoke now also proves native detail preview flags for every reserved managed rental and anonymous denial of private previews. Local and hosted identity classes remain separate; dedicated hosted has only four private standing rentals and no synthetic publication grants. Preview receipts: `docs/evidence/{local,hosted}-listing-preview-native.json`. Browser acceptance is recorded separately; positive hosted traveler inquiry/contact retry, actual transport-failure UI behavior, profile-completion/date-handoff browser paths, providers and full whole-product acceptance remain open. Editable Wander/Figma remains the next phase after functional acceptance.
