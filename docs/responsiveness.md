# Measured owner responsiveness

Research refreshed October 25, 2026 from Furnished Finder's [response rate](https://support.furnishedfinder.com/hc/en-us/articles/52699055726363-What-is-the-Response-Rate), [response time](https://support.furnishedfinder.com/hc/en-us/articles/54012247629083-What-is-a-Response-Time), [what counts](https://support.furnishedfinder.com/hc/en-us/articles/52699209889819-Understanding-Your-Response-Rate) and [one-time reset](https://support.furnishedfinder.com/hc/en-us/articles/53982554236443-How-Do-I-Reset-My-Response-Rate) documentation.

Each independently rented listing has a private percentage of qualifying traveler-started conversations answered within an inclusive 24 hours. Only the first traveler message and first native in-app owner reply count. Inquiry text enters the same conversation, so a subsequent inquiry or follow-up in that conversation does not start another measurement. Owner-initiated conversations and housing leads are excluded. Booking decisions, phone calls and email replies are not counted. Unanswered new conversations are included immediately; the dashboard explains that the rate can change while the 24-hour window is open. Clients cannot label a normal message as a housing lead without a native request binding.

The rate uses conversations started in the last 90 UTC calendar days, including today. If none qualify, the last three since the account's reset, if any, provide the fallback. Excellent is at least 75%, Needs improvement at least 50%, and Poor below 50%; no measured conversations means Fresh Start. Full precision determines eligibility, with one decimal displayed. Private analytics selection exposes each property's rate; portfolio selection asks the owner to choose a unit.

Public response time uses only actual replies to conversations started in those 90 calendar days. The implementation declares an upper-median response band, with inclusive thresholds at one hour, eight hours, one day, three days and seven days. Furnished Finder does not disclose its exact typical-time algorithm or numeric meaning of a few days; this is our explicit measured algorithm, not a claim to reproduce an undisclosed formula. No measured reply means no public promise. Public queries return only the label and require current public eligibility. The unsupported fixed 24-hour profile badge is removed because time is specific to each rental space. Private percentages/counts/reset metadata are not public. These metrics do not yet change search ranking.

An owner with a measured rate below 75% may confirm one account-wide reset. The server checks current eligibility, ownership, explicit all-space confirmation and unused account entitlement atomically. A timestamp starts a new rate epoch for every rental space. Existing messages, old-conversation replies and public response-time history remain; old replies cannot enter the new rate. The reset cannot be repeated. The browser dialog names all rental spaces and initially focuses Keep my rates. Actual reset acceptance is covered in native function tests; no shared development owner reset is consumed during browser QA.

Native first/reply tracking and per-day counts commit in the same message transaction. Retry references cannot duplicate either. Indexed reads use at most 180 daily rows, three fallback records, one coverage record and exact source lookups. One-time reset bounds daily epochs to two. A paged, resumable 25-conversation adoption records original native first messages and indexed first-owner-reply candidates; it never infers timestamps from lastMessageAt or treats unknown legacy origin as known. Unknown legacy coverage is disclosed. No percentage or public time is returned until adoption completes. An hourly tick refreshes the rolling window and resumes interrupted adoption; the window can remain cached until the next successful tick. No message content is stored in aggregate rows.
