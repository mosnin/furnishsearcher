# Private owner property directory

Convex remains the backend. Furnished Finder's current [property and unit help](https://support.furnishedfinder.com/hc/en-us/articles/51593395190299-How-Do-I-View-My-Property-or-Unit-Listing) documents address/headline/property-number search, state/city/status filters and hidden units (updated October 2, 2026; checked October 26). This implementation uses the existing app UI.

`ownerDirectory.list` authenticates the active landlord and derives ownership from that account. It does not accept another owner ID. A new `(landlordId, createdAt)` index returns at most ten newest candidates per request. Keyword tokens match normalized private address, headline, public property number (including compact spelling), native ID and unit name; city is exact after normalization, state is a validated postal code. These private fields are not added to a public search index.

Filters run on each bounded owner page. A page with no matches retains its cursor. My Listings explicitly offers Continue searching, distinguishes partial from exhaustive no matches, and reports matching rentals loaded rather than a portfolio total. Apply and Clear reset pagination. Include hidden units defaults on and excludes only child units with an explicit false publication request when switched off; pending and legacy unknown-intent units remain available. Current statuses are live, approved but not live, incomplete content, pending current staff approval, and rejected. An approved older revision cannot appear approved/current. Expiry remains account billing authority: missing payment proof is not relabeled as an expired property or given invented per-property prices. The pending human billing-model decision still applies.

Cards preserve edit, public view, map confirmation, shared units, availability, feature, publish/hide and guarded delete actions. They display the owner-only address, property number and unit name. Historical raw view counters are labeled legacy. The owner home now loads only five candidates using this query, labels its metrics as recent-listing metrics, uses actual current live status, and reports unmet publication requirements instead of claiming a requested listing is live. Manage all leads to the full directory.

Validation: 473 tests in 43 files pass, including seven new directory cases: 127-record traversal across twelve empty filtered pages; ten-candidate limit; ownership, anonymous/tenant/offboarded denials; address/headline/ID/unit/location filters; hidden child versus root/pending/unknown intent; current eligibility and stale approval; updated data/creation-time ordering; and numeric headline tokens that must not match substrings of unrelated property numbers. TypeScript, Next production build, local native push and dedicated development Convex push pass.

Hosted native and browser receipts are recorded separately in `docs/evidence/hosted-owner-directory-*.json`. No cloud paid/identity/publication grants, real provider deliveries or actual public rentals are created for acceptance. Hosted unit creation still requires real publication prerequisites, so child-unit filter semantics are proven in isolated native tests, not represented as hosted paid unit acceptance. The legacy public owner-profile `getByLandlord` compatibility API remains separate; this change removes it from both private owner directory and home, without claiming that all legacy public reads have been migrated. Whole-product/provider/public acceptance, billing model and the subsequent Wander/Figma phase remain open.
