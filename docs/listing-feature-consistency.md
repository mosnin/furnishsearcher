# Consistent rental feature labels

The owner editor previously exposed Pet Friendly, Parking and Utilities Included as both dedicated switches and independent amenity checkboxes. A private browser fixture reproduced a checked Pet Friendly amenity with the pet switch off. That could display a pet-friendly amenity beside a no-pets rule and disagree with native search/contact criteria.

New/edit forms now show those three choices only as dedicated labeled switches. Convex create and partial-update transactions derive the overlapping amenity labels from the corresponding flags. Other amenity labels remain independent, with trimmed, case-insensitive deduplication. An amenity-only update cannot turn on a dedicated feature, and turning a flag off removes its label. Partial writes preserve the other flags and normal ownership/revision/publication checks.

Legacy listing detail/list projections and search-card projections derive these same labels without mutating stored listings or approval state. Pure search and housing-request amenity matching use the same interpretation, preventing an old contradictory label from satisfying a requested feature. Enabled flags can satisfy their amenity alias even when an older stored array omitted it. Search URL normalization continues to recognize the existing aliases.

All 398 tests across 36 files, TypeScript and Next production build pass. Four regression cases cover native create/partial write consistency, owner boundaries, legacy read-without-rewrite, and legacy false-positive/false-negative search and housing matching. A guarded local native flow checks create, flag-only and amenity-only updates, foreign-write/anonymous-read denial and cleanup of only its own private fixture. No paid/identity fixtures or publication are involved. Receipt: `docs/evidence/local-listing-features-smoke.json`.

The hosted owner-gallery workflow uses actual reserved Clerk sign-in and visibly synthetic images in a newly created private listing. It does not send a synthetic address to a geocoder, publish the rental, purchase a subscription or grant identity/billing exceptions. Registered unused images retain their normal recovery period after cleanup. Whole-product and real provider/publication acceptance remain separate. Convex remains the backend; no reference UI styles are adopted.
